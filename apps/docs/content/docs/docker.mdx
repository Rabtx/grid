Run the Grid stack with Docker Compose. Fragments live under **`docker/compose/`** and are merged by the root **`docker-compose.yml`** via [`include`](https://docs.docker.com/compose/how-tos/multiple-compose-files/include/) (Compose **v2.20+**). Compose files follow the Compose Spec (**no** top-level `version` key).

## Layout

| Fragment | Contents |
|----------|----------|
| `docker/compose/postgres.yml` | Postgres 16, named volume, healthcheck |
| `docker/compose/api.yml` | The Grid API (`apps/api/Dockerfile`, Bun) |
| `docker/compose/web.yml` | Next.js web (standalone image) |

See **`docker/README.md`** for the manual `-f` fallback.

## Setup

1. **Copy env file** (from repo root):

   ```bash
   cp env.docker.example .env
   ```

   Set `JWT_SECRET` and `AUTH_TOKEN_SECRET` (32+ characters). Adjust ports if needed.

2. **Build and start the stack**:

   ```bash
   docker compose up -d --build
   ```

3. Open:

   - Web: http://localhost:3000
   - API health: http://localhost:4000/api/v1/health

## Ports

| Service | Host port (default) |
|---------|---------------------|
| Postgres | 5433 (container 5432) |
| API | 4000 |
| Web | 3000 |

## Notes

- The API runs migrations on startup when `RUN_MIGRATIONS=true` (default); uploads live in the `api_data` volume.
- The web image is the landing page only. `NEXT_PUBLIC_CONSOLE_URL`, where its "Sign in" and "Open Grid" go, is baked in at **build** time (typically `http://localhost:3001`).
- Host-only API/web development: `docker compose up -d postgres`, then `bun run dev`.
