Grid uses a strong default architecture that is intentionally overridable.

## Principles

- Keep apps thin; keep reusable behavior in packages.
- Prefer module public entrypoints over deep internal imports.
- Keep domain logic separate from transport and framework concerns.
- Enforce boundaries with automated checks, not only conventions.

## Layering

### `apps/web`

- `src/app/*` is routing and composition.
- `src/modules/*` is feature-level UI and workflows.
- `src/lib/*` contains framework-agnostic helpers for the app.
- `src/components/*` contains reusable visual components.

### `apps/api`

- `src/modules/*` holds feature modules: `routes.ts` plus plain functions for logic and queries.
- `src/http/*` holds cross-cutting HTTP pieces (envelope, errors, validation, sign-in check,
  rate limits, request ids).
- `src/config/*` holds validated environment configuration.
- The schema and migrations live in `packages/db` (`@grid/db`), shared with the launcher.

### `packages/*`

- Packages should remain app-agnostic and not import app aliases like `@/...`.
- Shared packages expose public entrypoints and avoid framework lock-in when possible.

## Enforcement

- Run `bun run architecture:check` locally and in CI (import boundaries + kebab-case naming).
- Boundary checks currently validate:
  - no `@/...` imports inside `packages/*`
  - no deep web module imports (`@/modules/*/*/*`) from outside `src/modules/`
  - no cross-app relative imports (`../../apps/`)
  - kebab-case file/folder names under TS/JS `src/` (allows dotted names like `auth.test.ts`, route groups `(auth)`, and `[id]` params)
