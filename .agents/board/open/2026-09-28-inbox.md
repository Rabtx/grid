## What

Roadmap B4. An Inbox page (and a sidebar entry with an unread count) listing what needs the
person, across projects: an agent waiting for approval or input, a turn that finished while they
were away, a turn that failed, and (when GitHub is connected) a review requested or checks failing
on their pull requests.

## Why / Context

Today the only signal is a push notification or noticing a thread's spinner stopped. The events
exist: the runner's chat hub already calls an attention hook for `turn_end` and `approval` when
nobody is watching (`ChatHub.onUnwatchedAttention`, used by `apps/runner/src/push/notifier.ts`);
pull requests come from `apps/runner/src/github/pulls.ts` (`review-requested:@me`, checks). The
prototype's Activity list (`routes/design/app-prototype.tsx`, `ActivityItem` in the kit) is the
look.

## Proposal or Ask

- **Runner** (`apps/runner/src/inbox/`): keep inbox items in the runner's SQLite (id, workspace,
  kind, project, thread id, title, detail, created, read/done). Add items from the same attention
  hook as push (without replacing push); mark a thread's items read when someone opens it. For
  GitHub, compute on request (cached for a minute): review requests and failing checks on the
  person's open pull requests for linked projects. Routes: `GET /inbox`, `POST /inbox/:id/read`,
  `POST /inbox/read-all`, `POST /inbox/:id/done`.
- **Console** (`modules/inbox/`): an Inbox page (Unread / All), each item with its project, time
  and one primary action (Open thread, Review, Approve when it is an approval), done/read on hover
  (desktop) or swipe/long press (phones). A sidebar entry "Inbox" in the top group with the unread
  count (kit `Count`), kept fresh while the app is open.
- Follow the sidebar rule: pages that span projects sit once in the top group.

Definition of done: leave a thread, let its turn finish or ask for approval, and it shows in the
Inbox with a count in the sidebar; opening it clears it; a requested review shows when GitHub is
connected.

## Scope

**In scope:** the new inbox modules (runner and console), the sidebar entry, routes and wiring.

**Out of scope:** email, automations reporting here (Phase C), mentions (Phase E).

## Validation

- Runner tests: items from the attention hook, read/done, per-workspace isolation, GitHub items
  from fixture `gh` JSON.
- Console tests: list, actions, unread count.
- `bun run lint`, `bun run typecheck`, `bun run architecture:check`, kit guard; phone screenshot.
